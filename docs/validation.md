## 2026-10-01 真实模型复核

使用用户已配置的官方 DeepSeek API，模型 `deepseek-v4-pro`、推理 `max`，请求输出上限 8192 tokens。独立 DSH Home 与一次性 Vite React 项目，实际 API 调用会产生费用。第一轮因嵌套 Windows 沙箱 ACL 配置失败而取消；改为正常用户启动宿主后，DSH 的 `workspace-write` 会话完成第二轮。

插件选中标题和按钮，生成正常请求，通过当前会话 queue 发送。模型仅从 `src/main.tsx` 的 JSX 提示自行定位 `src/style.css`，把桌面标题 72px 改为 60px，保留手机 54px，把两个视口的主按钮改为 `#635093`。模型执行构建，Windows 子进程权限拦截后，经一次性批准 `npm run build` 通过。测试代理没有代写这轮页面改动，也没有补充 CSS 文件定位提示。

独立浏览器检查两个视口的计算样式、原文案；源码快照确认仅这一个 CSS 文件有两处替换，因此原 JSX、字体、手机字号与交互代码保留。独立构建再次通过，插件完成采集、逐项接受、关闭后重开和 HTML 导出。验收点击由测试代理在检查通过后完成，并不代表用户已人工验收。

真实轮次持久化 `turn/start`→`turn/end` 耗时 **127.338 秒**，包括构建审批；基线采集 **2.438 秒**，候选采集 **1.998 秒**。这是单次测量，不是性能承诺。模型用量为未缓存输入 16,233、缓存读取 215,936、输出 6,339 tokens；取消的首轮也有用量，金额未从账单核验。

此次发现相近亮度的颜色变化在原图像阈值下漏计：手机按钮已变紫，比例显示 0%。阈值已修正；相同截图重新计算为桌面 **4.41%**、手机 **2.69%**。旧记录展示和报告会重新计算派生指标，原截图、源码与验收决定不变。另做新鲜浏览器采集与旧候选对照，比较规则下未出现额外变化。最终 13 项单元测试、2 项浏览器测试及类型检查、构建通过。

本轮证明的是这个简单 Vite React 示例的元素意见→真实模型源码修改→截图与代码验收闭环；未证明复杂项目、多轮反馈、视觉理解、多模型或其他框架质量。模型没有读取基线图片，意见定位依靠文本和 JSX 提示。更多细节见 [real-model-validation.md](real-model-validation.md)。
